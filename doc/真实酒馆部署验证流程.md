# 房车真实酒馆部署验证流程

本流程验证玩家在真实酒馆发送消息、DVS 正文前筛选与规划、模型生成正文、DVS 请求变量模型、作者脚本结算、保存变量，以及「旅行手册」重新读取并显示结果的完整过程。界面验证覆盖小悬浮框和四个 Tab，排除高德 Key 与安全密钥的填写、修改和保存。

执行前核对用户对实际部署、模型请求和测试数据写入的授权。执行结果按文档生命周期另存验收记录，不能把本流程的目标当作已通过结果。本仓库构建角色卡，不构建或部署 SQLite Helper 插件；需要更新插件时先按插件公开安装说明准备并获授权，再执行本流程。

## 验证入口与范围

房车默认开启筛选与规划，当前完整路径是：**原生发送消息 → 输入增强模型先规划再筛选 → 保存用户消息的增强记录 → 正文模型使用入选资料及规划生成完整正文 → DVS 自动请求变量模型 → 应用补丁 → 保存并读回 → 悬浮栏更新**。重生成或新 swipe 可复用已有增强记录，无须再次请求输入增强模型；实际开关及是否复用要读回确认。`DVS.regen()` 只更新最新 AI 回复当前分支的变量，不重新生成正文。这里的分支指酒馆同一回复下可左右切换的 swipe。

核对正文完整成功前没有发出变量请求，一次正文完成只启动一次变量工作；有限重试另按实际请求次数记录。停止、生成失败或切回旧 swipe 不触发新更新。普通自动流程不额外调用 `DVS.regen()`，手动重试作为单独场景验证。完整入口契约见[作者手册](https://github.com/q3boy/st-sqlite-helper/blob/master/doc/dvs/指南/DVS作者使用手册.md#主动更新最新回复的变量)。

| 验证对象 | 本轮检查 | 范围边界 |
| --- | --- | --- |
| 输入增强 | 根据实际开关核对完整准备数据、规划与筛选结果、用户消息记录和正文发送副本 | 不预先规定模型选择或剧情文本；复用时按当前业务键读取原行，展示快照不作为当前数据 |
| 正文生成 | 原生发送、真实请求与完整回复、当前状态注入、下一轮使用更新后的状态 | 不创建固定 AI 正文，不替换或模拟模型响应，不以独立 API 调用代替酒馆生成 |
| 变量更新 | 真实模型请求、原始补丁、六表变更、本轮结算、消息关联与保存 | 不预先写入想要的结果，不通过 SQL 或修改聊天文件制造成功 |
| 悬浮栏 | 点击、拖动、主题、宽窄布局、四 Tab、展开收起、持有人切换、数据刷新及卸载 | 悬浮栏读取当前聊天最新 AI 回复当前分支；回看旧正文不切换成历史面板 |
| 高德 | 帮助界面，以及已有有效配置下的地图显示、缩放、位置变化和主题 | 不填写、修改或提交配置，不填假 Key；没有有效配置时记录地图功能未测 |
| 保存 | 公开查询、聊天文件中的分支关联、SQLite 文件只读核对、刷新重开 | 界面更新和 `onUpdate` 通知都不证明文件已经保存 |

不扩展为全量插件回归、格式与模型横向测评、故障注入或数据迁移。模型采用当前可用的正文、输入增强与变量配置，记录实际模型和输出格式。确需切换 API 时等待用户配置完成，已有有效配置直接复用。

## 部署前准备

### 保护原状态与选择对象

开始前记录扩展启用状态、服务状态、存储来源、相关设置和本轮涉及对象。保全本轮会改变的主题偏好，记录浏览器缩放、窗口尺寸及原角色／聊天，结束时恢复。记录插件启动可能新建的文件，不能等打开卡片后再备份。对本轮会修改的现有角色、世界书、聊天、助手脚本、设置及数据库保存原始副本和路径；数据库备份先确认相关写入与后台保存结束，只读取得副本并核对可读，不在写入过程中复制后便声称备份完整。未准备好恢复来源前不执行写入。

复用用户指定的现有酒馆地址、浏览器和扩展安装，不另建酒馆、不修改 Docker。执行前记录实际网址、插件目录和存储目录；不假定固定端口或本机路径。SQLite 优先复用现有有效本地目录授权；缺少授权时由用户亲自选择目录并确认，代理不能代点浏览器权限确认或绕过限制。若实际使用 OPFS，按该模式在当前站点读回并注明，不能用本地文件证据代替。

使用房车当前源文件和**本轮专用角色／世界书／聊天**。先只读检查 [同步配置](../tavern_sync.yaml)：当前 `房车` 配置指向 `index`，目标为「房车慢生活」。如果酒馆中该目标已有业务数据，不直接 `push 房车 -f` 覆盖。在本库 `.test-data` 建立临时卡片副本，并在本库 `tavern_sync.yaml` 登记唯一的本轮专用配置：设置专用的酒馆名称、本地索引路径和导出路径；复制当前业务规则、初值及索引中全部启用脚本，仅区分验证对象名称。原对象不改，临时配置结束后移除。

至少建立两个专用聊天：A 用于连续对话与分支，B 使用相同开场白验证新聊天初值及切换。全部用当前 DDL 新建，避免把旧聊天未迁移的物资数量列当成新整数约束。保全或登记将创建的角色、关联世界书、助手脚本、聊天、数据库编号和文件，恢复清理只处理这些对象。

### 核对构建与加载

1. 核对 Git 工作区、[package.json](../package.json)和当前卡片产物。记录扩展构建编号，以及状态栏脚本的构建编号、SHA-256 和源文件对应关系；两套构建分别记录，不混成一个编号。已有产物确实对应当前源码时可直接使用；需要更新状态栏产物时，把 `CARD_RV_BUILD_DIR` 设为本轮独立的 `.test-data/房车真实酒馆/<本轮目录>/statusbar-build`，再运行 `bun run build:check`。不使用会复制到卡片脚本目录并打包的 `build`，把该输出接入专用卡，不能使用默认固定目录覆盖此前临时产物，也不覆盖已有验证附件或业务卡。
2. 复用已安装且与当前卡片接口配套的插件。若本轮确需更新插件，按另行授权的插件安装流程准备产物，保留当前安装副本及启用状态；房车仓库没有插件构建命令。切换前先核对需要保留的数据已经保存，再走插件原生关闭流程；关闭不会强制保存尚未落盘的业务修改。
3. 确认只启用本轮选定的插件版本；确有切换时刷新相关酒馆页面，再开启服务。记录页面与 Worker 的实际构建编号，核对二者配套且与所选插件产物一致，存储来源、权限及服务状态可用。
4. 插件就绪后，核对目标酒馆中酒馆助手的同步连接脚本已开启，并只连接本轮页面；角色卡的业务脚本不负责同步连接。在本库根目录运行 `bun run sync push <本轮专用配置名> -f` 推送单张专用卡，按工具输出等待连接和明确结果。`-f` 允许创建或覆盖内容，先确认目标属于本轮范围；多个网页连接或无法确认目标时停止推送。使用读回的配置名，不使用 `all`、`watch` 或 `pull`，不更新同步工具。推送前确认索引引用的状态栏脚本是第 1 步隔离构建输出。
5. 在酒馆读回角色、世界书和三个启用脚本：DVS、状态栏、主世界书版本检查。确认 DVS 脚本的 `dvs_enable`、`dvs_input_inject`、`dvs_plot` 实际值，它唯一注册；状态栏脚本（界面标题「旅行手册」）订阅注册状态并只读取，版本检查脚本独立运行。实际 Helper 脚本环境要支持当前预编译 Vue 产物，运行版本不配套时先停止，不能只从本地编译器版本推断可用。

卡片中 DDL／INIT 保持停用是正常配置，DVS SQL 读取忽略该开关；已启用的 NAR、RULES、DATA 内容分别按[世界书分流规则](https://github.com/q3boy/st-sqlite-helper/blob/master/doc/dvs/指南/DVS作者使用手册.md#选择世界书条目的用途)参与对应请求。推送成功、开关已开启和小框出现都不能单独证明初始化通过。

### 记录初值与准备观察方式

打开新聊天 A，等待注册与 INIT 完成，通过 `DVS.getState()` 读取六表，同时核对初层消息关联和文件。当前[INIT](../世界书/DVS-INIT.sql)的主要基线如下，执行时以实际读回为准：

| 对象 | 初始预期 |
| --- | --- |
| 世界 | `2026-06-05 10:30`、中国、晴；省份／城市／区域为精确「未知」 |
| 主角 | 当前玩家／Persona 名称，房车驾驶室，资金 120000000，粉丝 10000000 |
| 房车 | 油 1000 L、电 72 kWh、水 1000 L；家旁边的露天停车场；行车状态驻车，拓展状态收起（拓展与升顶全部收起） |
| NPC | 无记录，角色 Tab 显示空提示 |
| 房车物资 | 24 行；咖啡豆 4 袋、昆仑山矿泉水 12 桶、鸡蛋 36 枚等；数量为非负整数 |
| 随身物品 | 当前玩家名下 `iphone 17 pro max`，1 部，正常满电 |

不要对开场白调用 `DVS.regen()` 代替 INIT。开场白 regen 使用空起点，不重跑 INIT，不能用它验证普通回复从已有房车储量出发的结算。

采用现有浏览器能力观察真实请求与响应。发送第一条消息前确认能保留：正文请求实际内容、生成结束后的完整 AI 正文、变量请求中的起点与表结构、每次实际变量响应的原始内容和顺序。只保留本轮目标请求，去掉认证头、API 密钥和高德配置；不归档完整私人设置或全量网络记录。网络观察不得拦截替换正文／补丁或改变请求顺序。

需要单独验证主动重试时，使用已展开状态栏右上角的「重新更新变量」，它直接等待 `DVS.regen()`，期间禁用并在失败时显示原因。此按钮不生成新正文、不另行注册 DVS、不改作者回调、不直接写业务表；无需另加一次性助手按钮。使用 SDK 读取结果的临时工具仍只针对专用聊天，完成后删除。

## 每轮真实对话怎样核对

下列步骤是所有对话共用的核对顺序。消息位置 `messageId`、分支序号 `swipeId`、变量索引编号 `fid` 和业务行编号 `rid` 分开记录；不能把消息位置当作 fid，也不能直接读取业务表最后插入的一行当作当前状态。

1. **记录起点。** 固定聊天 A、最新待生成位置及前一个 AI 回复当前分支。通过公开 DVS 查询保存前一 AI 状态的六表，作为本轮真实起点；第一轮来源为已初始化的开场白。记录玩家实际名称。
2. **真实发送。** 在酒馆输入本轮用户消息，点击原生发送。默认开启输入增强时，先记录本次是否复用；新请求核对其准备数据、世界书候选、先规划后筛选的返回及实际请求次数。读回用户消息的 `<DVSInputInject>` 记录，观察其中的屏蔽条目、业务键及规划；查看面板核对保存快照和可选检查摘要。正文发送副本应使用当前入选资料与规划，检查摘要不进入正文。关闭或本次跳过时正文使用完整准备数据且不附规划。再观察真实正文请求中的状态与起点相符；NAR 使用作者的显示副本，例如 NPC 用「关系阶段」，不把省略的「好感度」「相遇情境」当成数据库字段丢失。SQL 条目、变量专用规则、筛选规则和规划专用条目不应作为普通世界书内容混入正文请求。新候选默认保留、用户记录重做／清除及独立 `reInject()` 按本轮改动选择验证，操作含义见[输入增强接口](https://github.com/q3boy/st-sqlite-helper/blob/master/doc/dvs/指南/DVS接口与进阶用法.md#输入增强接口)。
3. **保存正文事实。** 等待真实生成结束，保存用户消息、完整 AI 正文及目标分支。流式中途显示不是完成证据。正文是否落实测试行动，按实际全文确认；`<scene_info>` 是场景开始环境，世界表应记录正文结束状态。生成失败或为空先记录，不伪造回复补齐场景。
4. **等待自动变量更新。** 观察正文成功后自动发出的变量请求，期间保持聊天、目标分支和正文不变，不再手动调用 `DVS.regen()`。保存变量请求：本轮用户消息／正文、完整六表起点、作者规则、虚拟表结构及实际扫描背景。表结构包括 `本轮结算`，补丁顶层仍为 `Analysis` 与 `UpdateCommands`。每次自动重试都记录；最后写入采用哪次补丁，要能对应到实际请求顺序。
5. **独立推导结果。** 从本轮起点和最终被接受的原始补丁推导六表最终值，再按作者结算规则独立计算油、电、水。不能以执行后的数据库反推模型输入，也不能直接调用被测 `preUpdate` 作为唯一计算依据。
6. **读回数据库。** 等待本次更新完成或明确错误后，重新取得目标的 `DVS.getState({ messageId, swipeId })`，逐表读取并与独立预期比较。省略更新的真实字段应沿用起点值；新增行由 DDL 填默认值。`本轮结算` 不出现在最终业务表、楼层索引或消息变量中。
7. **核对悬浮栏。** 界面应在变量通知后自行重读；不刷新页面、不切聊天、不关设置面板来掩盖刷新缺失。展开总览及相关卡片，逐字段对照本轮读回；小框与大框使用同一轮数据。保留更新前后截图，读取完之前不把保留的旧数据判断为最终结果。
8. **核对保存。** 更新成功表示数据已在数据库内存中提交；文件保存仍需按「文件保存证据」一节读回 SQLite 与聊天文件。保存证据齐备后再发送下一轮，下一轮正文请求也要核对采用本轮保存的起点。

## 模型波动与成功标准

“希望它发生”与“正文实际发生”分开记录。测试输入要求 NPC 登场、加水或购买，不证明这些事已完成；正文没有发生时该场景记为未覆盖，继续用自然对话补足，不直接改变量凑结果。用户已经明确决定的行动仍按作者规则进入变量模型判断，正文与用户行动矛盾时保留原文并记录差异，不用单一来源掩盖矛盾。

| 判断层次 | 如何判定 |
| --- | --- |
| 场景是否覆盖 | 查看本轮用户消息和真实正文。是否真的行车、停留、补给、转交或消耗，具体数值是否明确，分别记录 |
| 模型输出结构与定位 | 解析格式、表名、完整业务键与字段符合注册结构。随身物品须同时包含 `持有人`、`物品名`；本轮结算用 `keys: {}`，数组和对象保持原生类型 |
| 模型对业务的判断 | 明示收支、明确时长／距离和归属作逐项观察；模型漏记、冲突、单位错误或重复时长记录为模型／规则偏差，不悄悄采纳。自由描述、好感度、粉丝增量、未明示的日照／时长等不要求命中预写常数，不单独作为插件接入门槛 |
| DVS 和作者脚本执行 | 已接受补丁必须按起点准确应用，JS 结算、非负与容量限制、精度、主键匹配、继承字段、消息关联和虚拟数据删除必须一致。不允许以 LLM 有波动解释确定性计算错误 |
| 界面与保存 | 界面逐项等于当前目标数据库的显示格式；磁盘数据与关联、刷新重开一致。模型偏差不影响发现界面漏刷或文件未保存 |

一轮可同时记录「结构／执行／显示通过」和「正文要求的补给漏记」。存在明确业务偏差时不能笼统写“完全符合预期”；有条件执行成功也不能把未覆盖的功能记通过。

核心场景遗漏时优先下一轮补一句明确行动，仍生成真实正文。必要时可原生重新生成，但将原结果和新分支分别保留；不反复抽取直到出现喜欢的业务数值，不用成功分支覆盖此前失败。少量补充仍不能形成所需场景时，记未覆盖或偏差及原因，结束该项，不无限请求模型。

### 油、电、水的独立预期

以本轮来源储量和被接受补丁内 `本轮结算` 的实际行程为输入，按[资源结算设计](房车场景与资源结算设计.md#js-计算)逐事件计算。活动消耗／补给／额外消耗按顺序处理，每次限制在 0 与容量之间；行车耗电与补电合并，持续补充轮末加回，最后油水保留 1 位、电保留 2 位。独立计算用十进制运算或人工明细，不复制作者 JS 整段实现。

例如起点为油1000、电72、水1000，实际补丁只有铺装行车60km／90min及随后驻车30min，没有持续补充：油 `1000−60×0.35−0.5×0.1=978.95`，最终979.0；电先 `min(72,72+1.5×0.5)=72`，再减0.4，最终71.60；水 `1000−1.5×2.5−0.5×2.5=995.0`。这个算例只说明核对方法，不是对话必达的固定答案；模型实际记录不同，就重新计算并另记记录差异。

`FULL` 在事件发生处补满，不能全部挪到轮末。持续补充的时长可与活动重叠，但不增加经过时间。没有本轮结算时作者脚本保留起点储量，不继承上一轮虚拟输入，也不接受模型直接写储量替代结算。明示消耗与补丁不符时记录模型偏差，但 JS 仍必须精确执行实际接受的输入。

## 连续对话场景

按下表推进同一聊天 A，每轮都执行共用核对。示例可照录或按前轮结果改地点与姓名；不重写开场白。故事时间沿用卡片的 2026 年 6 月，不能用执行当天日期替换。每轮均检查相关数据刷新，不只在最后一轮截图。

| 场景 | 可发送的真实用户消息 | 重点观察与读回 |
| --- | --- | --- |
| 出发与驻车 | 「第一站选杭州余杭区的良渚文化村。现在从家旁停车场出发，走铺装路，导航显示本段60公里，我开90分钟到停车场，然后停车休息30分钟。结束时仍在车内，不展开拓展舱。」 | 场景时间、国家省市区域天气；行车和驻车的实际记录、资源结算、车况与拓展；主角和房车位置。目的地是故事地点，不要求地图一定查到精确停车位 |
| 结识与采购 | 「我在停车场遇到两位成年旅行者林溪和周宁，聊聊她们的旅行经历和各自近况。随后在附近商店买2袋与车里同规格的咖啡豆，实际付款160元，放进厨房柜子，再回车旁和她们交谈。」 | 真实 NPC 登场／人设与角色表；昵称、同行、位置、状态、好感度和完整详情对照保存值。咖啡豆同名合并、整数数量、说明和位置；资金只按实际完成的明确收支观察，不预写好感度 |
| 外出与个人物品 | 「房车继续停在刚才的停车位，我步行到村里的咖啡馆，把自己的iphone借给林溪拍照，拍完她就还给我。林溪把自己的一支旅行手电筒正式送给我，但她自己的旅行背包仍由她持有；回停车场前，我买一条个人用充电线，付款50元。」 | 主角位置与房车位置分开；外出只按对应系数结算。借用不改变手机归属，赠送／采购按实际正文记录随身物品完整复合键。确认正文和保存数据中玩家与林溪各自有物品后，再验证持有人切换。不强迫赠送事件一定发生，未发生则补充真实对话；未形成第二持有人时该界面状态仍未覆盖 |
| 包装使用与直播 | 「回到房车后，我取一点已经开封的咖啡豆煮咖啡，还没用完这袋。再把一盒奶制品用完，盒子暂时留下。用手机直播分享今天的旅行，随后关闭直播，把拓展舱展开准备休息。」 | 咖啡豆部分取用不产生小数袋数；奶制品按整盒实际用尽扣减，保留说明／状态；粉丝增量作观察，界面必须等于保存值。行车状态保持驻车、拓展状态写为展开，房车卡标签显示「拓展展开」并换用展开图；两个字段的取值必须落在 DDL 允许的范围内，写错取值的情况另行记录 |
| 补水与额外消耗 | 「接下来一直在营地车旁休息30分钟，中途用车载清水洗装备，额外用掉20升，随后在营地水龙头把清水箱实际加满。不要把桶装饮用水倒进清水箱，也不购买或丢弃桶装水。」 | 驻车时长、额外消耗水20、补水FULL的实际记录顺序；水量与容量限制；公共桶装水不因清水补给自动转换。没有补丁事件就记录漏记，不能凭补满后的界面推测事件已正确执行 |
| 下一轮读取与零数量 | 「在下一段回复中先说说现在的车况、储量和物品情况。随后我把车里剩下的全部奶制品用完，空盒都暂时保留；这一轮结束时不再有可用奶制品。」 | 正文请求读取上一轮最终数据；没有继承上轮补水／额外消耗。实际用尽后有保留行时数量0仍显示，不能被真值过滤隐藏；没有按规则形成该结果则记业务偏差／该界面状态未覆盖 |

持续补充若在实际正文中出现，按原始输入一并独立核对。需要明确补证太阳能、风电、雨水时，用一个补充真实回合描述白天无遮挡驻车、风机实际部署和一段降雨结束后放晴；分别保存模型估计的时长及雨强，核对轮末加回结果，不预先写这些输入。若电水已满而无法观察增加，保留容量限制结论，不能把数值没变当成补充事件未执行；可选择已有较低储量的分支继续真实对话，不直接改库降低数值。

## 界面检查与字段对照

在初始化后先验证空角色与初值；出现 NPC、物资变化及多持有人后再验证有数据界面。所有对照读取当前最新 AI 分支六表，字段清单以[状态栏设计](状态栏设计.md#数据来源与显示)和 [data.ts](../状态栏/data.ts)为准。

### 数据显示

| 区域 | 逐项核对内容与格式 |
| --- | --- |
| 小悬浮框 | 日期时间显示 `MM.DD HH:mm`，城市和区域；水、电、油三条对应各自储量／容量。没有资源数值、单位或额外拖动按钮；进入大框后对照同一份数据 |
| 总览场景 | 区域标题，国家／省份／城市，日期、时间、天气；世界表取正文结束时状态，不强行等于第一段场景块 |
| 总览主角 | 标题显示「主角」；位置、状态、资金、粉丝。玩家宏名称用于随身物品默认持有人。万／亿显示按原值除对应单位并保留至多两位小数，原数据库数值不变 |
| 总览房车 | 油／电／水原数值、1000／72／1000容量及单位；条长为限制到0～1的储量比例，百分比四舍五入到整数。另核对状态、行车状态、拓展状态与所在地点，配图类型和车辆标签按这两个字段选择，不从插画推断车况。场景时段标签对应剧情时间；浅色的配色和配图按剧情时段，深色保持固定主题与夜晚配图 |
| 角色摘要 | 姓名、已知昵称、年龄、身份、同行状态、当前位置、状态、好感度。正好感度有加号，0和负值保留，不显示关系阶段代替好感度 |
| 角色详情 | 相貌、身材、穿着、生活背景、当前处境、核心特质、行为模式、在意与反感、说话风格、相遇情境、对主角观感、心声与 NSFW 信息；与完整保存值比较，不与 NAR 的删字段副本比较 |
| 房车物资 | 物品名、整数数量、单位、状态、存放位置及直接显示的完整说明；同名采购不重复成两张当前卡片，0行仍可见 |
| 随身物品 | 按持有人原名分组；物品名、数量、单位、状态，卡片直接显示完整说明，持有人只在顶部选择区显示，无虚构存放位置。切换持有人只显示对应复合键的行，不要求数量取整 |

精确「未知」及缺少值按设计显示「—」，不能过滤数字0、负好感度、已知的「无」或「未知原因」。只对本轮实际出现的值声称真实覆盖；没有自然形成的特殊值可引用程序测试范围，不能造一份 UI 数据后写成对话验证。日期切片和短进度条可用界面只读数据核对，必须同时目视截图检查，不能只看 DOM 数字。

### 已有高德配置时

只读取并复用专用角色原本有效的配置，不从业务角色复制密钥，也不打印输入框原值。没有配置时验证帮助和地图占位不阻碍其它 Tab，地图显示／缩放／标记更新明确记未测；不把高德申请或填写当作对话验证门槛。

有配置时展开总览，核对地图容器、供应商标识、主角／房车图例与缩放。真实地点查询结果决定标记是否存在，不能要求模型自由地点一定命中，也不能用城市中心补点。主角外出而房车不动时，分别对照实际查询文本和响应；有坐标才判定标记更新，无结果则检查对应标记清除、位置文字保留。已有坐标下切主题，地图保持 fresh 样式，主角／房车标记与图例 SVG 保持固定深绿，面板图例背景随主题变化。收起／切 Tab 后返回尺寸正确，地图拖动不拖外框。服务失败保留实际提示，非地图字段仍可用。查询响应和截图仅保留必要位置证据，不含密钥。

## 分支、聊天与刷新

主线形成可识别的六表变化后补下面操作。每个新生成分支仍使用真实正文模型与变量模型；不直接构造消息事件。

| 操作 | 核对方式 |
| --- | --- |
| 同一回复再次变量更新 | 完成并保存第一次结果后，再调用一次regen，保留两次真实补丁。普通回复都从前一AI回复出发，独立计算各自预期，不能从第一次结果再扣一次。两次模型估计可能不同，不要求全部业务值相等；标准占位标签和返回 JSON 数据块各自唯一，数据块替换成本次返回，正文不因重复更新不断增长 |
| 原生重新生成／新swipe | 原生生成第二份正文，记录新的分支身份，等待自动变量更新并保存。保留第一分支的起点／补丁／结果，与第二分支分别核对；未完成变量更新时的数据不可读提示不能被当成新分支已成功 |
| 切回已有分支 | 左右切换已成功保存的两个分支；不触发regen，悬浮栏自动匹配对应fid的六表，卡片和储量都不串分支。两个结果相同仍核对目标和查询，不能只凭数字不变判定没有切换 |
| 回看历史正文 | 保持最新分支不变，只滚动到旧回复；悬浮栏仍显示最新状态，不跟随所看的旧楼层 |
| 删除最新AI回复 | 保存删除前证据，用原生删除本轮专用消息；当前最新AI改变后按DVS公开查询读回可用状态，悬浮栏跟随新目标。尚未发生的清理不要求立即清除全部历史物理行，不靠业务表行数判断正确性 |
| A／B聊天切换 | B新聊天读回INIT；从A切B不显示A的NPC、物品变化或旧地图标记，回A显示A当前分支。展开卡和持有人选择清除，主题偏好可保留 |
| 脚本停用与重启 | 仅操作专用角色两个脚本：界面脚本关后节点移除，开后只挂一个实例；作者DVS脚本关后数据清空，重新注册后读回。关闭／换到专用非房车测试角色后不留悬浮节点，返回后不重复订阅或显示两个框 |
| 刷新与重开 | 先完成下面的落盘核对，再原生刷新，重开同一聊天和分支。重新读回六表与fid、界面对应字段，核对主题偏好；不要求临时拖动位置、Tab或展开状态跨刷新保存 |

不在模型请求处理中为本轮增加切角色、关闭服务等故障场景。确实遇到错误时先记录目标、调用结果和原始响应，核对准备与版本，不重复点击或用刷新证明原写入取消。同聊天读失败允许保留旧值，但须有提示；跨聊天不能保留旧聊天值。错误原因未确认就保留现象，不能写成网络、权限或模型故障的既定结论。

## 文件保存证据

对话中至少保留初始化、第一轮有资源变化、六表内容丰富的主线终点、两个已完成分支及刷新重开的必要文件读回。每轮仍核对本轮消息关联与改变的业务数据确实已保存；相同未变字段不重复保存整套附件。

通过公开接口读取消息及分支变量，核对目标 `dvs.fid`；再只读服务器保存的专用聊天文件，确认同一分支的关联。对本地目录的专用聊天 SQLite 文件，用只读 SQLite 工具按该fid的完整索引解析六表行，再与公开 DVS 查询比较。**fid 是索引来源，rid 用来定位业务行**；数据库可能保留历史版本，不能用裸表全量行数或最后一行代替当前状态。

确认回复末尾只有一个 `<DVSUpdateData>` 数据块，保留完整返回 JSON（含 cot），默认折叠且点击可查看格式化内容。它记录模型建议，不能代替作者结算后的数据库值。下一轮正文和变量请求均应移除整个数据块；DVS 插件提供通用正则，卡片不重复安装。

同时确认没有物理 `本轮结算` 表、没有业务列或索引保存虚拟输入。标准正文标签的保存与独立悬浮框分开核对：房车卡不靠该标签挂载悬浮栏，也不为验证添加楼层正则。

后台保存按[保存契约](https://github.com/q3boy/st-sqlite-helper/blob/master/doc/sqlite-helper/契约/数据库与保存契约.md)处理，通知与固定等待时间不是保存证据。等文件可读且内容与目标结果一致后才记录成功；可以有限轮询只读文件，记录实际等待及读回结果。未到预期先核对是否仍在保存或明确报错，不能盲目重发变量更新。需要正常关闭服务取得稳定文件时，先确认必要业务修改已落盘，再关闭，不让关闭取消待保存任务后仍声称刷新验证通过。

刷新后重开同一目标再读回，既核对业务值，也核对消息关联和界面。仅在内存查到、文件未确认、刷新后失败分别报告，不合并为“保存通过”。
