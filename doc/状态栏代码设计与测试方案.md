# 房车悬浮状态栏代码设计与测试方案

界面标题「旅行手册」、小框按钮的无障碍名称「打开旅行手册」与栏目导航名称「旅行手册栏目」均在 `状态栏/App.vue` 的模板中定义。Playwright 按当前无障碍名称定位按钮。玩家点击纵向小框打开旅行手册，查看当前聊天最新 AI 回复的数据；没有地图配置时在地图区域填写两项高德信息，写入当前角色库后加载地图。视觉和字段布局以[状态栏设计](状态栏设计.md)为主，本文件维护代码入口、操作顺序与测试要求。

## 文件与构建

源码、构建与测试按以下入口维护。

| 入口 | 职责 |
| --- | --- |
| `状态栏/entry.ts` | 脚本启动、主页面挂载、事件订阅和统一清理 |
| `状态栏/App.vue` | 小框、大框、Tab 切换、拖动、主题、地图配置与帮助模态框；统一持有地图生命周期 |
| `状态栏/OverviewTab.vue` | 总览排版、资源显示和底部素材；地图通过插槽放入，实例仍由 App 管理 |
| `状态栏/CharactersTab.vue` | 角色摘要、展开资料和角色卡的页面内选择 |
| `状态栏/ItemsTab.vue` | 物资与随身物品共用平铺排版；通过 kind 区分位置字段与持有人筛选 |
| `状态栏/display.ts` | 小框与总览共用的资源名称、容量、单位及有类型的图标标识；时段判断、按行车与拓展字段选择配图和标签、资源分档 |
| `状态栏/Icon.vue`、`icons.ts` | 面板 Phosphor fill 组件映射；地图与图例共用固定深绿 SVG |
| `状态栏/data.ts` | 固定本次聊天／最新 AI／swipe，读取六表、转成显示副本、丢弃过时查询 |
| `状态栏/geometry.ts` | 可见窗口测量、可用尺寸与坐标限制；点击与拖动判断在 App.vue |
| `状态栏/amap.ts` | 地图独立 iframe、在线 SDK 加载、位置查询和地图清理 |
| `状态栏/env.ts` | 当前角色 `env` 表读取和两项配置共同写入 |
| `scripts/build.ts` | 用 Bun 和 Vue SFC 编译器预编译模板，构建单个浏览器 IIFE 脚本 |
| `scripts/browser-test.ts`、`playwright.config.ts` | 独立房车浏览器运行入口，产物全部在 `.test-data/card-rv` |
| `tests/core`、`tests/browser` | 房车作者业务和界面测试；其余 Helper／DVS 测试不搬入 |

Vue 编译器与运行时使用兼容版本。构建将 SFC 模板转为 render 函数，生产构建的 `vue` 导入改为脚本 iframe 已有的 `Vue` 全局导出，不打包第二套 Vue，不在浏览器用 eval／Function 编译模板。测试环境使用固定版本的真实 Vue runtime。脚本检查 Helper 全局 Vue 为兼容的 3.5 系列。编译器与模拟测试 runtime 使用 package.json 锁定版本；安装源码与 CDN 读回不代表真实酒馆中的运行结果。

构建聚合状态栏目录中全部 Vue 组件的样式，写入同一个 ShadowRoot。组件保留同一 Vue 应用，显示组件用 v-show 切换；角色展开状态与物品持有人各自保存在组件内，切 Tab 或收起不丢失，resetKey 随聊天目标变化时清除。物品不保留展开状态，所有字段直接显示。物品列表采用三列 CSS Grid，窗口不宽于800px时两列，不宽于520px时单列；同行 stretch 自动等高，长内容自然撑高，位置行左对齐，使用定位图标和顶部分隔线。两类物品共用组件，状态胶囊只用主题统一色，不按文字分类。总览宽屏采用左侧场景／房车、右侧地图／主角两列，窄屏按这两列的顺序纵向排列。只有房车卡底部放配图，宽度 100%，窗口按类型选择固定宽高比，只裁透明天空。角色展开用左右两个列容器组织资料，完整布局见[状态栏设计](状态栏设计.md)。

PNG 和 SVG 在源码中显式导入，构建为 data URL 随单个 IIFE 携带，运行时不请求本机素材地址。12 张房车母版来自 `状态栏素材/房车配图/`，1586×992 PNG 等比缩到 888×555，使用 Lanczos3、有损 WebP、品质 90、Alpha 品质 100 和 effort 6；原始 PNG 不变。三份 SVG 保持原字节和 viewBox，输出到各自的 `images/` 子目录。素材清单和许可见[资源说明](状态栏素材.md)。

`Icon.vue` 对面板使用 `@phosphor-icons/vue` 的 fill 组件；地图和图例使用固定深绿 SVG。图标与配图不接收指针，图片设置空 alt、`aria-hidden` 和 `draggable=false`。标题徽记由 `Emblem.vue` 按时段及主题绘制。

Tailwind 4 在构建时扫描状态栏的 Vue／TS 源码并编译，连同组件样式写入 ShadowRoot。`scripts/tailwind.ts` 将 `@layer properties` 外包的条件展开为无条件回退，使 ShadowRoot 内的边框、位移等变量有初值；找不到预期结构时构建失败。组件手写样式放入 CSS layer，避免压过工具类，不向酒馆主文档写入一份全局 Tailwind 样式。Tailwind 及 Phosphor 版本以 `package.json` 为准。

`build.json` 记录构建编号、脚本与源码哈希、Tailwind 版本及处理方式。每个资源记录源文件和输出相对路径、SHA-256、字节数、尺寸及 Alpha／viewBox。第三方许可输出为 `THIRD-PARTY-LICENSES.txt` 和 IIFE 注释；构建只处理源码明确导入的素材，效果图不进入脚本。高德 SDK 按官方方式在线加载。

构建入口 `scripts/build.ts` 默认输出到 `.test-data/card-rv/build`，可用 `CARD_RV_BUILD_DIR` 改变目录，相对路径从房车仓库根解析、绝对路径保持原位置；带 `--publish` 时复制最终脚本至 `脚本/状态栏.js`。命令用法见[本卡导航](README.md#构建与测试命令)。发布的脚本由 `index.yaml` 独立角色脚本引用，关闭按钮列表，不设置第二个 `dvs_enable`。类型配置覆盖 `.ts` 与 Vue 组件。`typecheck` 通过 Node 调用 vue-tsc 和本库 TypeScript 6 的编译器 API 检查 SFC，再检查测试 TypeScript。独立环境安装见[本卡导航](README.md#独立开发环境)。

## 主页面挂载与脚本启动

脚本 iframe 的 `window.parent.document` 中新增自有 host，内部使用 ShadowRoot 隔离酒馆样式。Vue 使用 render 函数挂载 ShadowRoot 中的容器，不依赖该环境能解析模板。host 使用 `position: fixed`，不放进可能带 transform 的聊天滚动区域。host 外层不铺满屏幕阻挡酒馆点击；只有可见框体和打开的模态框接收指针事件。

用角色脚本 id 生成唯一节点名。重执行同一脚本时，先调用旧实例的 dispose，再创建一个 Vue 应用；旧实例晚完成的异步代码不得删掉新实例节点。运行中的应用、监听、地图和 DOM 的所有权由一个本地实例对象管理，dispose 可重复调用。

`脚本/DVS.js` 创建 `AbortController`，把 `signal` 传给 `DVS.register()`，并在 `pagehide` 时调用 `abort()`，使本次等待中的注册失效或注销已完成的注册。旧脚本关闭不影响后启动脚本的注册；中止注册不承诺取消已开始的 SQL。界面等待 `waitGlobalInitialized('DVS')` 和 `waitGlobalInitialized('SqliteHelper')`，完成显示模型与控制器创建后订阅 `DVS.onRegistrationChange()`。订阅立即回报当前是否完成有效注册，随后持续通知重新注册及注销，支持作者与界面的两种启动顺序。界面卸载时取消此订阅。

作者重新注册时先取消旧 `DVS.onUpdate`，再绑定一次新订阅。作者关闭时清空数据显示并销毁地图，不继续用旧注册。同角色切换聊天保持作者注册，界面清除显示并读取新聊天。换角色时 Helper 角色脚本自动关闭，同时自身 pagehide 清理主页面资源。不要仅依赖 iframe 自动清理 parent 文档节点。

作者就绪后，界面通过 `DVS.getUpdateStatus()` 读取当前变量更新进度，并通过 `DVS.onUpdateStatus()` 继续接收变化；重新注册、作者关闭及界面卸载时取消旧订阅。自动更新和手动更新期间都禁用「重新更新变量」，请求准备、模型等待和结果处理显示「正在更新变量…」，重试等待显示下一次尝试编号。手动点击还保留本次调用的等待标记，直到调用结束，避免状态通知前重复点击。DVS 统一提供通知，卡片只保留手动调用失败的内嵌说明。

监听使用当前 Helper `eventOn(...).stop()` 或对应卸载方法，不假定返回值是裸取消函数。DOM 监听、ResizeObserver、requestAnimationFrame、媒体查询、地图回调和 Vue 统一由 dispose 释放。卸载后不再挂载、读取或写入。

## 数据读取与通知

初始启动、卡片注册完成和 `DVS.onUpdate` 调用 `requestRefresh()`。原生 CHAT_CHANGED 立即使旧查询失效并清空旧聊天；MESSAGE_DELETED、MESSAGE_SWIPED、MESSAGE_RECEIVED 等消息变化使旧查询失效并请求重读。这些事件不证明变量处理成功，也不调用 regen。按当前 Helper 实际常量名接入，核对顺序；与 onUpdate 重叠时合并读取。界面不推断变量更新或文件保存已经开始。

`requestRefresh()` 递增读取序号、标记 dirty，并立即检查当前回复目标；已有读取进行时不另开一批六表查询。目标变化即暂停地图并使旧地点回调失效，新显示副本发布后再查询。仅换聊天清空地址缓存，同聊天地址未变不重复联网。当前批次结束，若 dirty 再读取最新目标。每次读取开始记录当前角色、chatId、聊天对象引用、最新 AI 消息对象／messageId 及 swipeId。消息范围用现行 Helper API／SillyTavern.getContext，只读；楼层索引不等于 fid。

目标取最新一条 AI 回复的当前 swipe：跳过用户消息和旁白，隐藏的 AI 回复仍是候选，与 DVS 的目标选择一致。取得 `DVS.getState()` 的当前固定状态，读取世界信息、主角信息和房车信息单行，角色信息、房车物资、随身物品列表。全部成功并再次核对读取序号、聊天及 AI／swipe 未变时，一次替换显示对象。fid 只在控制器内部核对；数据只取 DDL 的显示字段，不把 rid、行对象方法或代理交给 Vue。此流程不声称六条查询是数据库快照；若读取期间又收到更新通知，丢弃这一批并重读。

读取过程中 Tab／展开／主题继续可操作。同聊天无状态或读取失败保留上次数据并明确标注；新聊天无状态显示空提示。部分表查询失败不发布半新半旧的一组数据。页面清空和目标变化也使地图请求失效。主角姓名使用当前 Helper 宏展开得到的玩家名称，不凭 NPC 表推断。

右上角「重新更新变量」由 `entry.ts` 将当前脚本的 `helper.DVS.regen()` 作为回调交给 App。App 在调用前同步设置等待标记，直到 Promise 结束才释放；失败交付原错误，组件已卸载或聊天已切换时不显示旧请求错误。不另写模型请求、SQL或数据发布流程，数据刷新继续由原 `onUpdate` 订阅完成。

格式化函数保留 0、负好感度、空字符串和「无」，只把缺少值及精确「未知」显示为占位。日期按已有 `YYYY-MM-DD HH:mm` 文本取月日时分，避免时区转换。资源条使用油／水 1000、电 72 的容量，条形比例限制在 0～1，数值文本保持原值；数据缺失不伪装为资源耗尽。列表 key 使用注册业务键，随身物品用二元键，不用可能冲突的拼接字符串。

主题为系统／浅色／深色，只有主题偏好可用卡片专属 localStorage 键保存，写入失败仍保留当前页面选择。位置、当前 Tab、展开卡片及持有人仅存页面内存；切聊天清除数据相关选择。`display.ts` 的 `timeOfDay` 读取剧情时间，`rvArtKind` 读取行车与拓展字段，按[配图规则](状态栏设计.md#房车状态配图)返回 drive、park 或 expand。总览结合主题选择四时段中的图片；只换状态或主题不重新挂载Vue、重置选择或重查地图地址。

状态栏及帮助框的滚动区域使用透明轨道、窄圆角滑块，滑块颜色跟随明暗主题，悬停和拖动时增强对比。样式只作用于状态栏自身的 ShadowRoot。

## 拖动与可见窗口算法

可见区域取酒馆主窗口 `visualViewport` 的 offsetLeft、offsetTop、width、height；不可用时取主窗口 innerWidth／innerHeight。尺寸、pointer.clientX/Y 和 DOM rect 统一为 CSS px。禁止把 devicePixelRatio、visualViewport.scale 再乘到已是 CSS px 的坐标。主窗口 visualViewport resize／scroll、window resize 和框体 ResizeObserver 变化，合并到一个动画帧内执行重新测量。浏览器缩放与手机捏合缩放要分别验证，不能用修改 deviceScaleFactor 代替。

框体先获得实际可用宽高再限制坐标。设当前可见边界为 L、T、R、B，实际尺寸 w、h，正常边距 m=8：

```ts
// 伪代码；限制前先使框体不大于可见范围，空间不足时将边距缩至 0。
x = clamp(x, L + m, R - m - w);
y = clamp(y, T + m, B - m - h);
```

当上限小于下限，不可直接套 clamp。先缩小边距、重新排版和测量，再用有序的区间计算；可见高度仍容不下完整小框时允许小框正文内部滚动，整个外框仍在窗口内。大框先限制 width 与 max-height，标题栏 `flex-shrink: 0`、内容 `min-height: 0; overflow:auto`。标题控件能换行且收起按钮不压缩。极小窗口至少保留收起控件可见，不凭固定 900px 宽度保证操作区。

拖动采用 Pointer Events 和 pointer capture。小框整个区域是拖动表面；大框仅标题文字及空白区域起拖，button/input/select/a 等交互控件排除。主按钮按下记录起点，累计位移超过 5px 才算拖动，pointermove 使用当前位置差更新；每帧钳制，pointerup 再测量一次。拖动后的浏览器合成 click 必须被消费，不展开小框。pointercancel／lostpointercapture 收尾并释放；取消不模拟点击。Enter／空格单独展开，不受上次鼠标拖动残留影响。面板内容与地图可以自然滚动，地图拖动不能带动外框。

隐藏的大／小框切换后等 Vue nextTick，再读取实际尺寸并限制位置。可见区域变化中正在拖动时重新基准化指针起点和框体坐标，避免下一次 move 跳回旧位置。输入帮助模态框使用主窗口可见范围，自身内容内部滚动；弹出时聚焦关闭按钮／标题，关闭后回到原帮助入口，Escape 关闭。焦点循环直接读取主页面 ShadowRoot 的 activeElement，不用跨 iframe 的 instanceof 判断元素类型。焦点不能落在被遮罩的小框或背景页面。

## 高德配置表与保存

配置属于当前角色，不是楼层剧情。使用 `SqliteHelper.char` 的固定代理；不要放进聊天库 DDL 或 DVS uniqueKeys，不把配置加入模型输入、世界书或状态栏正文。

```sql
CREATE TABLE IF NOT EXISTS env (
  key TEXT PRIMARY KEY NOT NULL,
  value TEXT NOT NULL
);
```

| key | value |
| --- | --- |
| `amap_key` | 用户申请的 Web端（JS API）Key 原值 |
| `amap_sec` | 同一 Key 对应的安全密钥 securityJsCode 原值 |

读取时先查 sqlite_master 确认 env 存在；query 明确报 `DB_UNINITIALIZED`，或 sqlite_master 确认表不存在时才显示空配置，不为了显示先创建文件。`SqliteHelper.char` 为 null 时提示「请先打开房车角色聊天」，禁止保存；`DB_MISSING`、权限、服务及其它错误保留原错误提示，不能伪装成没填 Key。已有表结构不兼容时报错，不 DROP、不迁移已有任意 env 表。仅读这两个键，其它记录保留。页面通过「更改地图配置」可以再次打开两个输入框；普通显示不暴露已存原值。

用户点「保存并显示地图」才写入。两项去掉首尾空白，非空后取得当时的 char 固定代理，一次 `transaction` 包含 CREATE 和两条参数绑定的 UPSERT。使用 `INSERT ... ON CONFLICT(key) DO UPDATE SET value=excluded.value`，不要拼接输入到 SQL。表创建和两条数据共同提交，失败不留下部分新配置。提交期间禁用重复提交，用户切换角色则旧固定代理不能改写新角色；即使旧写入完成，旧界面结果也不能显示在新角色。

按现有 Helper 结果判断成功：`committed:true,persisted:false` 是内存已提交，文件后台保存。界面可立即读回并加载地图，提示「配置已写入，文件由助手在后台保存」。不写「已经落盘」，不新增公共保存方法或通用写入重试。失败沿用 Helper message 并保留输入；`SQL_COMMITTED`／`SQL_SAVED`／`SQL_UNKNOWN` 不作为普通失败鼓励重新提交，也不按正常成功继续加载地图，先停止依赖该返回的流程，用户重新读取已存配置核对。明确未执行／已回滚才允许修正后手工再保存。刷新后读取与真实文件读回的验证范围分别报告。

保存成功提示显示5秒后清除；再次保存、重新读取配置和组件卸载时取消旧计时器。错误提示不自动清除。地图Logo图片及「高德地图」文字位于独立iframe的同一个 `a.amap-logo` 中，通过该iframe内CSS隐藏；不隐藏 `.amap-copyright` 和其中的 `.amap-mcode`。

## 地图区域与帮助文案

缺少任一配置时，地图区域显示「填写高德地图信息后显示地图」，两个输入分别标为「地图 Key」和「安全密钥」，下面有「保存并显示地图」「如何获取？」。输入使用 password 类型并可切换可见；点击帮助打开模态框，不跳走、不清空已填写内容。保存失败保留输入，帮助关闭后可以接着填写。

帮助模态框正文使用以下意思，不要求玩家理解 API：

> 这两项是高德给你的地图通行证，用来让这里显示地图。只需要申请一次，同一角色的其它聊天也能继续使用。
>
> 1. 点击下面的「打开高德控制台」，登录或注册你的账号。
> 2. 找到「应用管理 → 我的应用」，创建一个应用，名字可以写「房车状态栏」。
> 3. 在应用中添加 Key。服务平台选「Web端（JS API）」，不要选「Web服务」。
> 4. 创建完成后，把页面上的「Key」复制到这里的「地图 Key」输入框；把同一个 Key 对应的「安全密钥」（页面可能写 securityJsCode）复制到「安全密钥」输入框。它们是两串不同的字符，不要填成同一串。
> 5. 如果高德要求填写可使用的网站地址／域名，按官方页面要求填写你访问酒馆的网址对应的地址。例如在浏览器里用 localhost 打开酒馆，就配置该访问地址；换成局域网 IP 后也要更新允许的地址。具体格式查看下面的官方说明。
> 6. 关闭这个说明框，填好两项，点「保存并显示地图」。地图加载失败时可以查看详细错误，并重新检查是否复制完整、服务平台是否选对、访问地址是否允许。
>
> 这里只用于你本机的角色卡；配置保存在当前角色数据库，不会发给剧情模型。地图加载和地点查询仍会把相关请求发给高德。导出或分享角色数据库时，应先去除自己的两项地图配置。

官方链接使用新标签打开： [高德控制台](https://console.amap.com/dev/key/app)、[官方创建说明](https://lbs.amap.com/api/javascript-api-v2/prerequisites)、[两项配置说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。获取流程以当前官方控制台和说明为准。安全密钥明文方式限本机使用，当前范围不建设代理服务器。

## 地图运行

首次展开总览时才取得 char 代理并读取地图配置；小悬浮框不读取配置，也不启动地图或地点查询。读取期间显示「正在读取地图配置…」，完成后显示地图或配置表单。收起、切 Tab 和再次展开沿用本次组件已读配置，不重复查询；明确点击重新读取或重新挂载组件时才重新读取。

高德 JS API 2.0 在线加载到地图自己的同源 srcdoc iframe，先设置该 iframe 内 `_AMapSecurityConfig.securityJsCode`，再请求 SDK。这种隔离用于更改 Key／切角色时彻底销毁旧 SDK 环境，也避免改动酒馆主窗口里可能已有的 AMap 全局。同一时刻最多一个地图 iframe，应用仍只有一个 Vue 实例。配置通过自己的同源代码传入，不放进卡片自己的页面／iframe 地址参数，不在日志、截图、验收文档或发布脚本中保存真实值；高德官方 SDK 加载 URL 仍按接口要求带 `key` 参数。回调名称固定在地图 iframe 内部，不泄漏主窗口全局。

只有展开总览、容器可见且两项配置齐全时才创建地图。切其它 Tab 或收起时保留单个实例但不查询新地址，回到总览再按当前数据同步；重新显示后更新尺寸。浅深均用fresh与固定色标记，切主题不重复查地点或重置地图视角。更改配置或换角色销毁旧地图 iframe。换聊天清除旧标记和地址缓存，不能显示旧地点。script 关闭彻底销毁。

只使用 AMap.Geocoder.getLocation，主角与房车分别组合国家、省份、城市、区域和位置文本，略过缺少值及精确「未知」，层级之间加空格。位置为空或精确未知时不查询，不用城市中心充当角色位置。每项取第一个有合法坐标的结果。当前图面使用对应返回的高德坐标，不混入 OSM 坐标。相同地址共用一次查询，本次页面缓存成功或无结果，数据位置不变不重查；错误不当成永久空结果，提供手动重新加载。

先更新或清除两个标记，再调整视野：两个点 fitView，一个点居中，零点不伪造坐标。高德 `setFitView` 使用 `instanceof Array` 判断标记列表，因此传入前用地图容器所属 iframe 的 `Array.from` 创建列表，保留原标记对象，fit最大缩放为16。`add`／`remove` 与坐标解析使用 `Array.isArray`，可以接受脚本窗口的数组，不需要同样转换，也不为其他地图调用增加包装。重合时仅用标记像素偏移区分，不修改经纬度。关闭地图点击弹窗与导航，保留缩放和供应商标识。浅深主题均采用官方 fresh 样式；地图标记与图例 SVG 固定使用深绿色 `#214D47`，面板图例背景读取当前主题的 `--legend`；地图标记不随主题改色。高德的逐要素自定义样式需要发布 styleId，且 styleId 必须与 Key 属于同一账户；分享卡由玩家填写各自的 Key，因此只使用官方预设样式。底图保持原不透明度，不通过整图染色压缩道路、水面、绿地和建筑之间的颜色差异。没有结果正常不显示相应图标，查询失败显示「地图暂时无法加载，位置文字仍可查看」和详细错误，所有其它 Tab 正常使用。

地理编码回调和 SDK 加载完成都要核对地图实例、配置、聊天与地址请求序号；已经过时的结果不渲染。每次网络操作有有限等待（建议 15 秒），超时交付错误，不后台无限重试。此等待不改变 Helper 写入、DVS 更新或文件保存契约。

布局断言与截图前，先等待目标文字和选择状态、当前可见图片逐张decode且naturalWidth>0，再等document.fonts.ready和Vue布局完成，对相邻测量的稳定矩形作判断。隐藏Tab切换后重新等待图片。地图等待模拟SDK创建、标记和fit日志，不用固定sleep证明步骤到达。收集pageerror和console error，失败先核对模拟准备与同步点。

每个状态不仅检查 boundingClientRect，还通过元素命中测试及实际 click 验证小框可以展开、收起按钮可以收起、标题栏可以拖动。设置面板打开和背景有高 z-index 控件时检查可见、可点击；采用合适的 host 层级，不依赖关闭设置面板。模态框通过 Escape／关闭按钮可关闭，Tab 焦点留在模态框内，关闭还原焦点。长内容滚动不能把标题栏滚出外框。

保存最终构建两主题四 Tab 宽窄截图，以及四时段、行车／驻车／拓展展开、小框、角色展开、持有人切换、长内容、矮窗、地图配置、帮助、错误与设置遮挡状态。布局按[状态栏设计](状态栏设计.md)核对，颜色按[主色值表](状态栏主色值表.md)核对，保留构建编号和脚本／源码哈希。旧效果图只对其仍适用的人物、物品及小框结构作参考。自动化使用假Key与明确标为模拟的高德地图，截图不能代替真实地图、酒馆或文件落盘证据。

参考旧效果图核对人物、物品排版时，使用尽量相同的示例数据，只修改测试数据。并排时只等比缩放到相同显示宽度，不拉伸，也不裁掉暴露问题的部分。确认稿是 AI 生成图，文字与地图不是像素基线，因此不设全屏像素差阈值；本机字形和模拟地图的差异如实说明，布局、错色、遮挡、变形和主体截断必须修正后重新截图。浏览器入口 `test:browser` 会重新构建生产脚本，截图对应的构建编号以该入口实际生成的 `build.json` 为准。

## 执行与交付边界

按改动影响运行本库类型检查、Bun／浏览器测试，并核对构建产物。房车业务与界面证据单独报告；本库模拟接口不能证明 Helper／DVS 的内部行为。

配置写入功能的最终审查核对固定 char 代理、事务和 char 字节重开读回。若需要实际酒馆安装验证，按[真实酒馆部署验证流程](真实酒馆部署验证流程.md)使用专用测试角色和测试 char 库，用户业务角色及数据库保持原状；部署与真实模型请求须另有授权，不能由实现和自动化测试授权推断。没有真实 Key 时不要求玩家先申请才能完成其它自动化测试，真实高德加载／中文地点查询保留为未验证项。

验收记录按功能组织在本卡`doc/验收记录/`下，构建源版本、实际测试、未测范围和用户确认分别记录。自动化产物放在 `.test-data/card-rv`，固定清理命令和范围见[本卡导航](README.md#清理与工具)。整体功能验收完成后按文档生命周期删除对应过程材料，不删除稳定授权目录或恢复所需备份。
