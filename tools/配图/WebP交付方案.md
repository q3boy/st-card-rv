# 房车配图 WebP 交付方案

采用 **12 张独立 WebP，保留完整透明天空，显示时再裁切**。宽窄版共用同一套素材，不拼大图，不提前裁掉天空，不缩小原始分辨率。

## 输入与编码参数

输入为 `状态栏素材/房车配图/rv-<状态>-<时段>.png`：

- 状态：`drive`、`park`、`expand`。
- 时段：`dawn`、`day`、`dusk`、`night`。
- 共 12 张，均为 **1586×992、RGBA**。

| 项目 | 参数 |
| --- | --- |
| 输出方式 | 每张 PNG 分别编码为同名 `.webp` |
| 输出尺寸 | **1586×992**，不缩放、不裁切 |
| 编码 | 有损 WebP，`lossless: false` |
| 图像质量 | **`quality: 90`** |
| 透明通道质量 | **`alphaQuality: 100`** |
| 编码工作量 | **`effort: 6`** |
| 其他选项 | Sharp 默认值 |
| 透明度处理 | 保留输入 alpha，不重新抠图、不填天空、不额外阈值化 |

Sharp 的 WebP 参数：

```js
{
  lossless: false,
  quality: 90,
  alphaQuality: 100,
  effort: 6,
}
```

实验使用 Sharp 0.35.5、libvips 8.18.7、libwebp 1.6.0。下面的体积是该版本和这 12 张素材的实测结果，不保证更换素材或编码器版本后字节数相同。

## 实际显示方式

图片宽度跟随房车卡，底部对齐。文件保留天空，但显示区域只保留卡片需要的高度：

| 状态 | 显示区域宽高比 | 原图中显示的范围 |
| --- | --- | --- |
| 行车 `drive` | **1586:562** | y=430 到底部 |
| 驻车 `park` | **1586:562** | y=430 到底部 |
| 展开 `expand` | **1586:617** | y=375 到底部 |

可用固定宽高比的容器隐藏图片顶部，图片本身保持比例、靠下对齐：

```css
.rv-art {
  position: relative;
  width: 100%;
  aspect-ratio: 1586 / 562;
  overflow: hidden;
}

.rv-art.is-expanded {
  aspect-ratio: 1586 / 617;
}

.rv-art img {
  position: absolute;
  left: 0;
  bottom: 0;
  display: block;
  width: 100%;
  height: auto;
}
```

浅色模式按状态和当前时段选图；深色模式按状态统一选 `night`。切换时更换当前图片地址，无需拼图坐标表或修改 DVS 表结构、字段及规则。

宽版约 930 CSS 像素，窄版约 430 CSS 像素；实验按 DPR=2 检查。保留 1586px 原始宽度，不为达到宽版的 1860 个设备像素而放大源图。1000/860/800px 的候选在宽版已有可见细节损失，因此不作为宽窄共用方案。

## 打包与实测体积

正式打包方式为每张 WebP 转成含 `data:image/webp;base64,` 前缀的字符串，再放入 JS。每次显示其中一张；少显示几张不会减少已经打包进 JS 的字节。

| 项目 | 12 张合计 |
| --- | ---: |
| 原 PNG 二进制 | 19,271,822 B |
| 推荐 WebP 二进制 | **2,474,486 B** |
| WebP data URI 字符串 | **3,299,604 B** |
| 素材 JS，gzip level=9 | **2,460,996 B** |
| 素材 JS，Brotli quality=11 | **2,451,200 B** |

WebP 二进制比原 PNG 减少约 **87.16%**。压缩后的 JS 数值只包含实验的素材对象及导出语句，不是完整产品 JS 的体积。

## 选择理由与验证范围

同尺寸、同质量比较，拼图在本轮全部组合中最多节省约 2.02%，部分组合反而更大；同时增加定位维护和整图解码容量，因此采用独立图。

1586px／Q90 下，提前裁切的独立 WebP 为 2,651,700 B；保留天空的本方案少 **177,214 B，约 6.68%**。因此按“省 JS 空间”优先保留天空。提前裁切主要降低位图内存：本方案当前一张 RGBA 位图约 6.00 MiB，提前裁切约 3.40–3.73 MiB；这是宽×高×4 的容量估算，浏览器缓存和 GPU 内存另计。

这套参数已在独立浏览器预览中，以相同显示区域、430/930 CSS 像素宽和指定深浅底色检查；抽查未见新增白边、明显毛边或夜图灯光色带。全部图像解码后的 alpha 与编码前一致；可见区域平均 RGB SSIM 约为深底 0.976899、浅底 0.977207。它们是实验与样本目视证据，不是产品或真实酒馆接入验证。

## 编码脚本

[脚本/encode-webp.mjs](脚本/encode-webp.mjs) 按上述参数编码：

```bash
bun run encode-webp 状态栏素材/房车配图 <输出目录>
```

实验的完整报告和样例素材 JS 在被 Git 忽略的 `.test-data/rv-art-webp-test/`，随该目录清理可能不再存在；本文件保存选定方案与参数。
