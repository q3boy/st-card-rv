# 房车状态栏配图制作指南

本文记录第一轮房车配图（3 种状态 × 4 个时段，共 12 张）的做法、固定参数、检查方法和已踩过的坑，供以后增加新场景或重做某张图时直接照做。本目录（`tools/配图/`）保存制作用的脚本、提示词和可复用的底图；正式使用的 12 张融合图在 `状态栏素材/房车配图/`，WebP 编码方式见 [WebP交付方案](WebP交付方案.md)。

文件名里的状态和时段：

| 状态 | 含义 | 对应场景 |
| --- | --- | --- |

时段：`dawn` 清晨、`day` 白天、`dusk` 傍晚、`night` 夜晚。深色模式不单独出图，统一使用 `night`。

## 2. 固定参数（所有图必须一致，否则切换时车会跳）

- 融合图画布 1586×992。车辆图画布 1960×1220。
- 车辆图缩放到 0.437 倍，放在场景画布的 (404, 378) 位置。例如用 ffmpeg：

  ```bash
  ffmpeg -y -i scene.png -i vehicle.png -filter_complex "[1]scale=iw*0.437:ih*0.437:flags=lanczos[v];[0][v]overlay=404:378" in-composite.png
  ```

- 三种状态共用同一个位置和缩放：展开状态的车身（车头到后轮）和收起状态一样大，只是多出向上、向右的展开部分。
- 山脊线高度约在 y=459 到 546 之间，车顶（含行李架）约在 y=545，展开后二层顶板最高约 y=395，所以场景上方透明区足够容纳展开，不会被切掉。
- 车轮站在地面带中间：公路的路面带近边和营地地面都保持约 2 到 3 度向右上升，和车的接地线倾斜一致。

## 3. 工作模式：先做独立素材，再交给 codex 融合

1. 先准备独立素材：房车图（透明底）、场景底图（天空透明、没有车）。
2. 把房车按第 2 节的固定参数放到场景上，得到一张粗拼图。
3. 把粗拼图交给 codex，要求统一色调、加接触阴影、保持车和场景不变，并直接输出带透明天空的 PNG。这一步就是融合。
4. 其他时段不重新做场景，直接从“白天融合图”只改光照。

以后新增场景（例如雪地、海边）：先出这个场景的空底图，再按上面 2、3、4 步做 12 张。现有的房车图不用重画。

## 4. 新增一个场景的完整步骤

1. 出空场景底图。用 `scene-road-base-fullsky.png` 或 `scene-camp-empty.png` 当参考，要求保持同一机位、画布和地面带位置，只换地面内容和周围景物。山脊要求见第 5 节。
2. 抠天空。有两条路，先试第一条：
   - 直接要求 codex 输出 RGBA，山脊以上完全透明。本轮营地和公路的融合图都用这个办法成功了。
   - 不行（边缘发白或天空被填色）时，让 codex 把天空涂成纯品红 `#FF00FF`，再用 `脚本/defringe.mjs` 抠掉并去粉边。
3. 做 3 张白天融合图：行车、驻车、展开。展开那张要先让 codex 把驻车图里的车去掉，得到空场景，再放展开房车。
4. 从每张白天融合图改出清晨、傍晚、夜晚（每次只改一类：这里只改光照）。
5. 做第 6 节的检查，统一画布和透明度。
6. 放进状态栏模拟页，按状态和时段截图，对照对应时段的卡片背景色看是否协调。

## 5. 场景设计要求（本轮确认的）

- 山脊是一条平滑、起伏明显的线：3 到 4 个圆润丘顶，最高丘顶比最低鞍部高约 60 到 90 像素。山脊上不出现树、灌木、电线杆等细碎轮廓，这样抠边不会出问题。树只能出现在山前面。
- 不画远处的蓝灰色山脊和大面积山景，山整体偏低，最高处只比房车顶（含行李架）高出约 60 像素。
- 整体低饱和，不用鲜绿、亮蓝。这是装饰图，不追求真实。
- 公路场景保持用户提供的原图风格：黄色双中线、白色边线、右侧向远处拐弯。营地场景是压实的碎石土地、零星短草、几块石头、远侧原木围栏，没有车位线、路缘石、桌椅、帐篷。
- 天空整体透明，不画云。卡片背景自己透出来，浅色、深色卡片都能融合。

## 6. 时段光照标准与检查

### 时段标准（图本身符合时间，不去追卡片颜色）

| 时段 | 光照 | 车灯和室内光 |
| --- | --- | --- |
| 清晨 | 日出后不久：冷、柔、低对比；草和山是冷灰绿，地面冷灰，阴影冷蓝灰；只有最高山顶和车顶上缘有极淡的暖金。严禁粉、品红、紫、薰衣草、玫瑰、橙色调 | 车外灯全关，车窗只有很弱的暖光 |
| 白天 | 午后柔和暖光，低饱和，轻微薄雾 | 灯关 |
| 傍晚 | 日落前约半小时：低而斜的暖金光，受光面泛暖金，植被仍是橄榄绿褐，阴影暖褐；严禁整张图一层橙红滤镜，也不要粉紫 | 行车开大灯、示廓灯、尾灯；驻车只有车窗室内光；展开再加雨棚下小灯和二层护栏灯带 |
| 夜晚 | 晴夜微月光：景物压成深蓝灰到蓝黑，暗部仍有细节；灯和车窗是主光源，暖黄明亮 | 行车开大灯且路面有光束；驻车只有车窗光；展开加舱内光洒向甲板、雨棚筒灯、二层灯带、甲板前地面渐隐光晕 |

重要教训：清晨图不要为了和卡片的淡紫背景协调而把整张图染成粉紫。卡片颜色已经通过透明天空露出来了，再把地面和车染粉紫就成了滤镜。协调靠明度和饱和度，不靠同色相。

参考的状态栏卡片底色（取自模拟页截图）：清晨约 `#EBE5F3`，白天约 `#EAE2CF`，傍晚约 `#F3E2D5`，夜晚约 `#E8EAF1`，深色约 `#2A2620`。

### 检查清单

| 检查项 | 方法 | 合格标准 |
| --- | --- | --- |
| 画布尺寸和通道 | `node 脚本/alpha.mjs 图.png` | 1586×992，RGBA |
| 天空透明 | 同上 | 完全透明像素占 47% 到 52%（展开图略低，因为车顶伸进天空）；四角 alpha 为 0 |
| 不透明区 | 同上 | 模型输出的不透明区 alpha 是 253，最后统一提到 255（见第 7 节处理命令） |
| 山脊 | `node 脚本/ridgeprof.mjs 图.png` | 起伏幅度 60 到 90 像素，平滑度数值小于约 0.5 |
| 色相 | `node 脚本/hue.mjs`（先改脚本里的文件名列表） | 清晨整体色相 40 到 70、近中性；傍晚约 28；夜晚景物偏蓝；不允许景物偏粉红（色相 330 到 360） |
| 粉边残留 | `node 脚本/defringe.mjs` 末尾的统计 | 粉色明显（>20）的像素为 0 |
| 位置一致 | `node 脚本/regcheck.mjs <融合图目录>` | 同一状态的各时段相对白天，车的偏移不超过 2 像素 |
| 车不走样 | 把融合图和对应的白天图并排或来回切换看 | 轮廓、车窗、车头、支腿、展开部件（甲板、雨棚、二层顶板和立柱、舱内陈设）不变 |
| 深色底边缘 | 把图放在 `#2A2620` 底上放大看山脊 | 没有白边、光晕 |

## 7. 统一处理与截图

最后一步的统一处理（尺寸规整并把接近不透明的像素变成真不透明，边缘半透明像素保留）：

```bash
ffmpeg -y -i 输入.png -vf "scale=1586:992:flags=lanczos,format=rgba,geq=r='r(X,Y)':g='g(X,Y)':b='b(X,Y)':a='if(lt(alpha(X,Y),8),0,if(gt(alpha(X,Y),200),255,alpha(X,Y)))'" 输出.png
```

状态栏截图用模拟页 `.test-data/rv-statusbar-design`（验收后可能已清理，需要时按设计页重建）：

1. 把 12 张图复制到页面的 `public/art/`，用 `模拟页演示/OverviewTab.art-demo.vue` 替换 `src/components/OverviewTab.vue`。这个版本按 URL 参数 `?rvstate=drive|park|expand` 和卡片的时段选图，深色模式用夜晚图；收起状态图片区域高度比 1586:562，展开状态 1586:617（展开多出的高度用来容纳升起的二层）。
2. 开发服务器 `npx vite --port 5199` 已在跑时，把 `脚本/shot-art.mjs` 放到模拟页目录，依次运行 `node shot-art.mjs drive`、`park`、`expand`，截图输出到模拟页目录下的 `screenshots/`。
3. 截图完成后把 `OverviewTab.vue` 恢复原样，并删掉 `public/art/`。本轮已经这样还原，模拟页现在仍是原来的 `rv-parked.png`。

## 8. 脚本说明

都是 Node 脚本，不依赖第三方库，在 Windows 的 Git Bash 下运行。

| 脚本 | 用途 |
| --- | --- |
| `alpha.mjs` | 读 PNG：尺寸、通道、完全透明/半透明/不透明占比、四角 alpha |
| `ridgeprof.mjs` | 读透明通道，找每列的山脊线，输出最高/最低点、起伏幅度、平滑度 |
| `hue.mjs` | 计算整体和地面带的平均色和色相；需要先改脚本里的文件名列表 |
| `regcheck.mjs` | 比较同一状态各时段相对白天的位置偏移 |
| `defringe.mjs` | 抠品红天空并去粉边：`node defringe.mjs 品红图.png 输出.png 0.85`（最后一个参数是饱和度系数） |
| `keyfade.mjs` | 品红抠图加山脊向下渐变透明（本轮最终没有用渐变，保留备用） |
| `bbox.mjs`、`stats.mjs`、`wheels.mjs` | 量房车图的外框、整体色调统计、接地点高度 |
| `one.sh` | 调 codex-vision 做一次编辑，带超时并把日志写到文件 |
| `shot-art.mjs` | 状态栏模拟页按房车状态截图 |
| `encode-webp.mjs` | 12 张 PNG 按 WebP 交付方案编码：`bun run encode-webp <PNG 目录> <输出目录>`，在仓库根目录运行，使用已安装的 sharp |

## 9. codex-vision 在这台 Windows 机器上的做法和注意事项

下面的 `~/.claude/skills/codex-vision/` 是制图时使用的外部工具路径，不随本仓库提供；复用这段制图方法时替换为自己的安装路径。它不是角色卡构建、测试或使用现有配图的前提。调用方式（在 Git Bash 里）：

```bash
bash ~/.claude/skills/codex-vision/scripts/codex-vision.sh edit --fresh "<输入图绝对路径>" "<提示词>" --out "<输出图绝对路径>"
```

必须注意的几点：

1. **模型固定 `gpt-6.1-sol`。** 这台机器的 ChatGPT 账号不支持 `gpt-5.5`、`gpt-5.4`、`gpt-5.2`、`gpt-5-codex`，skill 默认模型已改成 `gpt-6.1-sol`。
2. **skill 已针对 Windows 修过四处：** 查文件修改时间同时支持 BSD 和 GNU 的 `stat`；识别新生成图时除了 `ig_*.png` 也认 `exec-*.png`；从会话记录取图的 Python 会逐个试 `python3`、`python`（Windows 上 `python3` 是应用商店占位程序，存在但不能运行），并把路径转成 Windows 能识别的格式；调用 codex 时加 `</dev/null`，否则后台运行会一直等标准输入。
3. **不能并行出图。** 并行时多个任务会取到同一张“最新生成的图”，造成两张图内容相同或串图。本轮第一次并行出清晨和傍晚就出现了这种情况。所有图都串行出。
4. **用 `CODEX_VISION_REF=<另一张图>` 可以给 `edit` 加一张参考图**（提示词里要写清第二张图只做什么用，例如只参考光照和色调）。用完要 `unset`，否则会带到下一次调用。
5. **图片路径用干净的绝对路径**，不要含 `..`，否则 codex 可能一启动就退出（退出码 127）。
6. **每次调用用 `timeout 540`，一次出一张图，约 1 到 2 分钟。** 超时或没有结果时先看日志文件，不要重复提交。
7. **出图尺寸由 codex 自己决定，**提示词里写的尺寸不会被遵守，输出常在 1586×992 或 1589×990 左右，偶尔差 1 个像素。所以统一尺寸放在最后一步用 ffmpeg 处理。车位置和大小的对齐靠“自己先拼好、再让 codex 融合”来控制，不靠提示词。
8. 停止后台任务时，先确认真的停了：停掉外层任务不一定会结束它的子进程，残留进程会继续往目标目录写图，把文件覆盖掉。这次是用终端面板里的 `Stop-Process` 结束的。
9. 每张图出来后先读一次透明通道、对着原图看车有没有走样，再决定是否继续往下派生。

## 10. 提示词写法要点

- 每次修改只做一类改动：改光照就不改结构，改山脊就不动车。提示词里要明确写“保持……完全不变”。
- 每张图都从它的基准图修改，不接力修改（A 改出 B，再从 B 改出 C），误差会累积。时段变体都从白天融合图出。
- 要求透明时写明“真实 alpha 通道的 PNG，山脊以上完全透明，没有天空色、雾、光晕”，并写“山脊边缘清晰干净”。
- 光照提示词里写明禁止的颜色（粉、品红、紫、薰衣草、玫瑰、整片橙红滤镜）。只写想要的色调，模型容易走偏成粉紫。
- 不要在提示词里指望精确像素。要对齐就自己拼好再让模型融合。
- `prompts/` 目录里的文件可以直接当模板，替换场景描述即可。

## 11. 已确认的取舍和限制

- 每个状态用一张融合整图，不再叠“场景层 + 车辆层”。想换场景时要重新融合 12 张，车辆图不用重画。`vehicles/` 里的 12 张独立车辆图保留为素材。其中清晨、傍晚、夜晚的独立车辆图是较早的光照版本（清晨带粉金调），最终图没有使用，新场景请从白天车辆图开始融合，再从融合图改时段。
- 深色模式统一用夜晚图，所以深色卡片里的配图时段可能和文字显示的时段不一致，这是已确认的设计。
- 模型输出的不透明区 alpha 是 253，已提到 255；山脊边缘有约 0.1% 到 0.3% 的单像素半透明过渡，是正常抗锯齿。
- 三张白天图的山色有细微差别（展开和行车略偏黄，驻车略偏灰绿），已确认可以接受。
- 夜晚展开图的甲板前光晕比较靠近车底，已确认可以接受。
- 树冠上有少量淡紫小斑点是树叶本身的颜色，不是抠图残边，没有处理。
- 以上图片没有放进产品。放进 `状态栏素材/` 或改状态栏的取图逻辑，需要另行安排，并要按那时的版式调整图片区域高度（收起约 1586:562，展开约 1586:617）。
- DVS 的行车状态、拓展状态字段和规则本轮没有改。
